# Windlass

A small notification manager: Spring Boot REST API, SQLite persistence, and a responsive vanilla JavaScript UI. No separate frontend build or database server is needed.

Detailed feature, API, persistence, deployment, and code documentation is in
[docs/README.md](docs/README.md), with a task index for AI agents.

## Run

Requires JDK 24 or newer. The Maven wrapper downloads Maven and dependencies on first use.

```sh
./mvnw spring-boot:run
```

Open http://localhost:8080. Create notifications, search by title/description/source, inspect metadata, edit, mark as seen, and delete from the UI. Unread cards are highlighted and the header shows the unread count.

Data is stored in `notifications.db` in the working directory and survives restarts. Set `DATABASE_URL` to change the SQLite JDBC URL (for example `jdbc:sqlite:/tmp/windlass.db`). Set `SERVER_PORT` to change the port. The app is intended for local use and has no authentication.

## Model

| Field | Type | Behavior |
| --- | --- | --- |
| `id` | UUID string | Generated by the server; immutable |
| `title` | string | Required, nonblank, up to 200 characters |
| `description` | string | Optional, up to 10,000 characters; defaults to empty |
| `notification_source` | string | Required, nonblank, up to 200 characters |
| `received_on` | ISO 8601 timestamp | Defaults to now on creation; retained on update if omitted |
| `unread` | boolean | Defaults to `true`; mark as seen to set `false`. Preserved when editing. |
| `external_links` | Map of labels to URL strings | Optional; defaults to `{}`. HTTP/HTTPS URLs only; shown as links opening in new tabs. Example: `{"Issue": "https://github.com/example/project/issues/1"}` |
| `metadata_map` | JSON object | Optional; defaults to `{}`; supports nested JSON values |

Existing SQLite databases are upgraded automatically; existing notifications receive an empty `external_links` map and start unread. Seen state persists across restarts.

## API

| Method | Route | Result |
| --- | --- | --- |
| GET | `/api/notifications` | List, newest received first |
| GET | `/api/notifications/{id}` | Get one |
| POST | `/api/notifications` | Create; returns 201 and Location header |
| PUT | `/api/notifications/{id}` | Replace editable fields; returns 200 |
| PATCH | `/api/notifications/{id}/seen` | Mark as seen; returns updated notification (safe to repeat) |
| DELETE | `/api/notifications/{id}` | Delete; returns 204 |

Invalid requests return 400; missing IDs return 404. PUT requires title and source; omitted description/metadata/external links reset to their defaults.

```sh
curl -i http://localhost:8080/api/notifications \
  -H 'Content-Type: application/json' \
  -d '{"title":"Build complete","description":"Ready to deploy","notification_source":"CI","metadata_map":{"branch":"main","build":42}}'
```

## Verify and package

```sh
./mvnw test
./mvnw package
java -jar target/windlass-0.0.1-SNAPSHOT.jar
```

Integration tests exercise the complete CRUD lifecycle, nested metadata, validation, missing resources, defaults, ordering, and static UI delivery using an isolated in-memory SQLite database.

## Docker image

Run with Docker Compose and persistent SQLite storage:

```sh
docker compose up -d --build
```

Compose mounts the named volume `windlass-data` at `/data`, where the app stores
`notifications.db` and SQLite journal files. Data survives container recreation
and `docker compose down`. `docker compose down --volumes` deletes this storage.
The volume starts with a separate database; it does not import an existing
`notifications.db` from the project directory.

Open http://localhost:8080. If that port is occupied, use
`WINDLASS_PORT=8081 docker compose up -d --build` and open http://localhost:8081.

Build the application image (including its integration tests):

```sh
docker build -t windlass:local .
docker run --name windlass-app --rm -p 127.0.0.1:8080:8080 \
  -v windlass-data:/data windlass:local
```

Open http://localhost:8080. The image runs as UID/GID `10001`, uses Java 25
with the project's Java 24 compilation target, and stores SQLite data under
`/data`. The named volume preserves notifications when the container is removed.
If using a host bind mount instead, give UID `10001` write access to that directory.
Stop any existing app on port 8080 first, or use `-p 127.0.0.1:8081:8080`.

The [Docker image workflow](.github/workflows/docker.yml) builds on branch
pushes, pull requests, `v*` tags, and manual runs. Builds on the repository's
default branch and `v*` tags publish to `ghcr.io/<owner>/<repository>` using
GitHub's built-in `GITHUB_TOKEN`; other builds only validate the image.
Default-branch images include the `latest` tag, releases use their Git tag
(e.g. `v1.0.0`), and published images also include a `sha-<short-commit>` tag.
Image names are normalized to lowercase by the metadata action.

The workflow requests `packages: write`; repository/organization settings must
allow GitHub Actions to publish packages. Images are built for `linux/amd64`.
The application Dockerfile is separate from `.devcontainer/Dockerfile`.
